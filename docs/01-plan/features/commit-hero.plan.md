# Commit Hero 기획서

> 작성일: 2026-09-30 | 단계: Plan | 근거: 사용자 인터뷰

## 1. 목적

GitHub username을 입력하면 공개 활동을 분석해 개인화된 RPG 카드를 생성한다.
한국 개발자가 “내 특징을 잘 잡았고 웃기다”라고 느끼는 경험이 최우선이다.
카드를 공유받은 사람이 자신의 캐릭터를 궁금해하며 생성하는 흐름을 만든다.
바이럴 효과는 출시 후 검증할 가설이다.

## 2. 합의한 사용자 경험

1. 로그인 없이 GitHub username을 입력한다. 본인, 친구, 유명 개발자 계정을 조회할 수 있다.
2. 약 5초 안에 카드를 보여주는 것을 목표로 한다.
3. 캐릭터 일러스트, username, 직업·칭호, 레벨, 핵심 스탯, 웃긴 한 줄을 표시한다.
4. 이미지로 저장하거나 공유 링크를 복사한다.
5. 공유 링크 방문자는 해당 카드와 “내 카드 만들기” 버튼을 볼 수 있다.

## 3. 카드와 해석 원칙

- 개발 습관과 코딩 취향을 함께 해석한다.
- 정통 판타지 직업과 개발자 유머를 결합한다.
- 직업마다 고정된 대표 일러스트를 사용한다. 개인별 AI 이미지 생성은 첫 출시에 포함하지 않는다.
- 일러스트가 크게 들어가는 수집형 RPG 카드 분위기를 사용한다.
- 한국어로 자연스럽고 친구처럼 짓궂게 표현한다. 별도로 제외할 농담 소재는 없다.
- 실제 관측된 특징은 과장할 수 있지만, 확인되지 않은 습관이나 사실은 만들어내지 않는다.
- 공개 활동이 적은 사용자도 웃으며 공유할 수 있는 캐릭터를 제공한다.
- 분석 결과를 사용자가 수정하거나 다른 해석으로 다시 뽑는 기능은 제공하지 않는다.
- 같은 데이터와 같은 분석 버전에서는 같은 대표 캐릭터가 나온다.
- 최근 1년의 활동으로 직업과 성향을 정하고, 누적 활동으로 레벨과 업적을 표현하는 것이 제품 목표다.
- 레벨은 활동량을 반영하고, 초반은 빠르게 오르며 고레벨부터 상승이 어려워진다.
- 능력치는 개발 성향을 반영하되 이름은 힘·민첩·지능·체력·행운 등 RPG 용어를 사용한다.
- 직업 종류, 스탯의 최종 목록과 데이터 매핑, 레벨 공식은 기술 설계에서 정한다.
- 업적의 산정 및 표시는 기술 설계에서 구체화한다. 합의된 공유 카드의 필수 요소에는 업적 표시를 추가하지 않는다.

## 4. 출시 범위

첫 출시: 공개 데이터 분석, 카드 생성, 이미지 저장, 공유 링크, 한국어 UI.
후속 기능: 기본 캐릭터를 유지한 의상·표정 등 외형 변형.
첫 출시에서 제외: 로그인, 비공개 활동 조회, 파티 구성, 사용자 간 비교 기능, 다국어.
분석 근거를 상세하게 보여주는 페이지는 첫 출시 필수 범위에 포함하지 않는다.

## 5. 기술 및 운영 조건

| 항목 | 합의 내용 |
|---|---|
| 프레임워크 | Next.js |
| 패키지 매니저 | Bun |
| 배포 | Vercel |
| 월 운영비 | 무료 우선, 최대 약 1만 원 |
| 첫 테스트 | 합의 시점부터 1~2주 내 소규모 테스트 |
| 테스트 계정 | ParkBG77 — https://github.com/ParkBG77 |

첫 테스트 목표 기간은 2026-10-07~2026-10-14다. 정확한 공개일은 확정하지 않았다.
외부 요금제와 기술 제약, API 응답 시간은 아직 검증하지 않았다.
ParkBG77 프로필은 이전 웹 조회가 실패해 실제 활동 분석을 수행하지 못했다.

## 6. 성공 기준

- 유효한 username으로 로그인 없이 카드를 생성하고 이미지 저장·링크 공유를 수행할 수 있다.
- 공유 링크에서 다른 사용자의 카드 생성으로 이어질 수 있다.
- 첫 테스터에게 어떤 해석이 자신과 맞았고 어떤 해석이 빗나갔는지 피드백을 받는다.
- “내 특징을 잘 잡았다”, “웃기다”라는 공감이 우선이며 공유와 유입은 후속 지표다.
- 생성 시간과 예상 월 비용을 측정해 5초 및 1만 원 목표와 비교한다.
- 정량적인 만족도 합격 기준은 테스트 규모를 정할 때 설정한다.

| 성향 추론 | 시간대·언어·활동 패턴의 근거와 해석 규칙, 데이터 부족 시 처리 |

| RPG 규칙 | 직업 분류, 레벨 곡선, 스탯 매핑, 칭호와 농담의 재현성 |
| 공유와 이미지 | 카드 렌더링, 저장 방식, 공유 링크의 결과 유지와 갱신 기준 |

| 제작 자산 | 직업별 일러스트 수량, 제작 방식, 사용 권한 |

## 9. 후속 결정: 프런트엔드 목업부터 구현

2026-09-30 사용자 요청으로 이번 구현 범위를 Next.js 기본 세팅과 프런트엔드 목업으로 한정했다.
백엔드 및 GitHub API는 연결하지 않는다. 분석 결과는 실제 사용자의 활동과 무관한 샘플이다.
샘플 카드 생성, 이미지 저장, 데모 공유 링크 복원으로 UI 흐름을 먼저 확인한다.
제품의 실제 분석 요구사항은 후속 백엔드 연동 단계에서 구현한다.

## 10. 후속 결정: GitHub 공개 데이터 전용

GitHub API 연동 시 공개 프로필, 공개 저장소 및 공개 활동만 분석한다.
사용자는 username만 입력하며 GitHub 로그인이나 OAuth 권한 동의를 요구하지 않는다.
비공개 저장소, 비공개 커밋 및 비공개 기여를 분석 대상에 포함하지 않는다.
공개 데이터에 없는 활동을 0으로 단정하거나 전체 이력으로 표현하지 않는다.
최근 1년·누적 활동 목표는 공개 API에서 실제 확보 가능한 범위를 검증해 구체화한다.
서비스 측 API 인증 방식과 토큰 사용 여부는 아직 확정하지 않았다. 공개 데이터 범위와 별개의 기술 결정이다.
현재 단계는 프런트엔드 목업이며 이 결정만으로 API 연동을 시작하지 않는다.
